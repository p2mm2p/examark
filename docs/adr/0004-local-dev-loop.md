# 本地开发流：轮询监视 + 标准库 HTTP，零第三方依赖

## 背景

工单 #8 要给 `emark-cli` 补上 `watch`（保存即重建）、`preview`（本地提供输出）与 `toolchain`（三者端到端跑一条流）。此前两个 crate 都是零依赖，而这两件事各有成熟 crate 可选：监视有 `notify`，HTTP 服务有 `tiny_http`、`axum`。要不要为此引入依赖，取决于两件事的成本对比：

- `watch` 的承诺是「保存后在人的感知范围内重建」。轮询一个小文本文件（每秒 4 次）的代价可以忽略；事件驱动的收益是零唤醒与毫秒级响应。
- `preview` 面对的是一个输出目录、一个人、一个浏览器。请求量决定了这里不需要连接复用、范围请求或路由框架。

## 决策

1. **监视用轮询**：每 250ms 读一次源文档，与上一份内容逐字节比对，不同就重建。不比对 mtime ＋ 大小——粗粒度文件系统与「改了内容却不改大小」的保存都会漏掉改动；源文档是文本，读一遍比判断「要不要读」更省心。首份快照在报出「正在监视」之前取，保证作者看到那行之后保存的内容一定被算作改动。
2. **HTTP 服务用标准库**：`TcpListener` 绑 `127.0.0.1`，一条连接一个线程，`Connection: close`，只认 GET 与 HEAD。路径先解 `%XX` 再按 `/` 拆，出现 `..` 一律 404——预览服务不能成为读任意文件的口子。
3. **`Cache-Control: no-store`**：重建后刷新浏览器该看到新内容。这一条是编辑循环的一部分，不是可选优化。
4. **四个命令同一套参数形态**：`emark <命令> <文档> [-o 输出目录] [--port 端口]`，`--port` 只用于 `preview` 与 `toolchain`；端口默认 8080，`0` 表示由系统分配。
5. **`preview` 先构建再提供**：独立运行 `emark preview 卷子.emark` 一条命令就能在浏览器里看到结果，四个命令的参数形态也因此统一。
6. **`toolchain` 三段的「依次」是进入顺序，不是互斥的串行**：构建 —— 服务 —— 监视 按这个顺序进入，构建只做一次；但服务与监视必须同时在跑（服务要一直开着才谈得上「刷新即见」），所以服务交给后台线程、监视留在当前线程。谁先谁后只是进入顺序，不是「一段跑完再跑下一段」。
7. **重建的产出用「写临时文件 ＋ 改名」落盘**：`preview`／`toolchain` 会在重建的同时提供这些文件，直接覆写会让正好赶上的请求读到半截 HTML。
8. **起步失败即退出，监视中的失败不中断**：文档读不到、首次构建失败、端口被占——都报错退出；`watch` 运行期间某次重建失败（作者正写错）只报错，监视继续，输出目录里留着上一次成功构建出的 HTML。

## 被否决的方案

- **`notify`**：事件驱动、空闲零唤醒，代价是引入 inotify／kqueue／windows-sys 等平台相关依赖树与事件去抖逻辑。本项目要的是「保存后 250ms 内重建」，轮询的代价（每秒读 4 次一个小文本文件）与它的收益不匹配。监视被收在 `watch` 一个模块里，将来要换是局部改动。
- **`tiny_http`／`axum`**：本地预览的请求量撑不起一个 HTTP 框架或异步运行时的依赖树。
- **绑 `0.0.0.0`**：会把作者的输出目录暴露到局域网。只绑回环。
- **端口被占时自动换端口**：静默换端口会让地址栏里的书签失效；改为明确失败并提示 `--port`。
- **`preview` 只提供已有输出**（`vite preview` 的语义）：那要求先跑过 `build`，否则浏览器里只有 404；`preview` 独立运行的承诺就打了折。

## 后果

- 保存到重建最多延迟 250ms。
- 监视只看源文档，不看引用的图片：换一张图不会触发重建，得重跑一次 `build`（图是二进制截图，v1 认为这可以接受）。
- HTTP 服务是最小实现：不做 keep-alive、不做目录列表、不做范围请求。将来若要加浏览器的热更新（SSE／WebSocket），这个模块要长一截。
- 内容类型表只覆盖手写 HTML 文档可能引用的几种（HTML、CSS、JS 与各图片格式）；认不出的按二进制流给，浏览器仍会下载，只是不带类型语义。
- 每次构建都会在输出目录里留下临时文件再改名过去；构建中途被打断（Ctrl-C）时，临时文件可能留在原处。
- 零依赖意味着构建不依赖网络、无平台相关代码；`cargo clippy --all-targets -- -D warnings` 与全测试套件是这次改动唯一的验证门。
