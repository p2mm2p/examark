# 文档结构：结构化元数据、内联答案解析、v1 不做题目 id

## 决策

1. **文档级元数据用结构化英文字段**：`title`、`exam`、`year`、`paper`、`region`、`source`、`duration`、`score`；键是封闭集合，未知名报错；`title` 可由 `exam`＋`year`＋`paper` 拼出。依据是真题卷首惯例（考试名＋年份＋卷别＋来源），且**卷面根本不印分值**（国考官方不公布），故没有必填的分值字段。
2. **答案与解析内联在题目块内**，卷末答案表由渲染器生成。真题公布版把答案做成独立答案表、教辅则题块内联；数据内联只存在一份，天然不会出现「题号对不上」，而卷末答案表只是渲染选项。
3. **材料与小题按相邻绑定**：`@material` 之后紧跟的题目都属于该材料，不写引用。QTI 用独立的 stimulus ＋ stimulus-ref 是为机器拼装与跨文档复用；手写文档里那不是收益而是负担。
4. **v1 不做题目 id**。调研结论（`docs/research/stable-ids.md`、`docs/research/question-bank-ids.md`）：位置序号删题跳号、中间插入要重排；内容哈希改一个错别字就换身份（genanki 的 guid、pandoc 的 auto_identifiers 都是这个坑）。唯一可行的是「与内容、位置都解耦的稳定 id」，但手写 id 会加重文档编写者的负担，且目前没有可接受的生成方案（仓库主人判断）。v1 沿用文档顺序的自动序号寻址，id 方案留待 v2 错题本需求落地时再定——调研已落盘，可直接复用。
5. **范围外**：不定项选择（上海市考）不在 v1，答案字段只接受单个字母；「分类内重新编号」属渲染层，不进格式。
6. **一个模块可以占多个模块分节**：分节声明一次模块，同一模块（尤其判断推理的四个子题型）写成若干个分节、各有自己的子分类。真实卷面正是这样印的（「一、图形推理／二、定义判断…」），比「一个模块内交错多个子分类组」更贴合书写与渲染；需要合并展示时由渲染层处理。

## 后果

- 父规范（#1）里「稳定寻址（文档 ＋ 序号）是 v1 的保证」须改写：v1 只有顺序序号，稳定寻址随 id 一起推迟到 v2。
- 父规范里「选项支持文本与行内 LaTeX，不支持图片」须改写为支持图片：图形推理的题干与选项都是图形，不放开等于整个子分类写不出来。
- 材料题不需要 id，`@material` 与后续题目的对应关系由解析器按相邻关系建立。
