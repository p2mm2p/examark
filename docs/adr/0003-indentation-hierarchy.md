# 层级用缩进表达（附五条护栏）

examark 的层级由缩进表达：`@module` 顶格，其下每深一级缩进 2 个空格，内容行比它的关键字深一级；块结束靠缩进退回，不使用闭合关键字。

## 背景

两种层级表达法都做过完整调研（`docs/research/hierarchy-markup.md`、`docs/research/indentation-blocks.md`）：

- 缩进敏感格式只在「同一块内不一致」时报错，**「整体合法但结构变了」一律静默**；YAML 规范甚至没有错误处理章节。
- 面向长散文的既有格式里，Fountain（剧本）显式忽略缩进、改用行首标记；唯一真·缩进散文块是 reStructuredText 的 directive 体，代价是规则极复杂且只发软警告。
- 调研的裁决句：语言不强制闭合关键字，是因为它们用 DEDENT 代替了闭合；而 DEDENT 的前提是「行首空白可信」——对粘贴进来的中文长散文，这个前提不成立。

仓库主人权衡后仍选择缩进语义，理由是**书写手感**：缩进写起来最顺眼、层级一眼可见，粘贴摩擦可接受。

## 决策

采用缩进语义，并以五条护栏把已知的静默风险转成硬报错：

1. 缩进只用空格；行首出现 TAB 报错。
2. 每层固定 2 个空格，不匹配即报错——不留「整体多缩进一层仍合法」的口子。
3. 内容行必须恰好比它的关键字深一级（`@stem` 的续行、材料正文同理）。
4. 结构行的合法缩进由 schema 决定：元数据与 `@module` 为 0，`@subcategory` 与 `@question` 为 2，字段为 4，内容续行为 6；缩进回退必须命中这些列之一，否则硬报错。
5. 不认识的 `@关键字` 一律报错，绝不静默当正文。

被否决的替代方案：显式闭合（`@material … @end`）、命名归属（`@subquestion`），以及二者叠加受检缩进的版本。

## 后果

- 粘贴路径上行首空白被吃掉时会**报错**而非静默变形：PDF 复制、聊天窗口与代码块都会剥掉缩进，作者需在使用前确认、或事后按报错补缩进。
- v1 明令不做序列化写回，因此没有自动缩进修复工具，这条摩擦由作者承担。
- 若将来要重新考虑，`docs/research/indentation-blocks.md` 已列出把缩进降级为「可选严格模式」所需的全套校验清单。
