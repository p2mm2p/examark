# 记号体系：行首 `@` 前缀的标记语言

examark 的块结构由行首 `@` 前缀的**英文关键字**界定；行级元素的参数到行尾，行内带内容的元素用 `@关键字{…}` 定界，无内容的行内元素是裸 token（`@blank`）。

## 背景

工单 #1 定了内容模型（可选元数据、模块分节、单选题、材料题）却没定记号。第一版实现采用了「中文行首标签 + 全角冒号」（`题目：`、`答案：`、`解析：`），落地后立刻被否决，三条理由：

1. **中文标签与正文无法区分**：作者书写时看不出 `题目：` 是关键字还是句子的一部分——记号必须自带可见性。
2. **语言不一致**：文档元数据的键是英文（`title`），正文标签却是中文，判据混乱。
3. **全角冒号不适合做结构符**：CJK 标点与行内定界符的冲突是已知解析坑（CommonMark issue #650 至今未解决）。

## 决策

- 结构一律 `@` 前缀 ＋ **英文关键字**：关键字是标识符，与代码标识符用英文同理；中文观感留在渲染层。
- 关键字分两级：**块级**（行首出现即开启新结构）与**行内**（属于内容的一部分）。
- 行级元素参数到行尾；行内带内容者用 `{}` 定界；`@blank` 无内容，是唯一的裸 token。
- **公式用 `@math{…}`，不用 LaTeX 惯用的 `$…$`**：`@` 家族的成员不设例外；花括号按 LaTeX 语法天然配平，`\{`、`\}` 为转义不参与计数；行内元素不允许跨行。
- 不认识的 `@xxx` 一律报错，绝不静默当正文。

## 被否决的方案

- **中文行首标签 ＋ 全角冒号**（第一版实现）：见背景。
- **Markdown 式 `#` 层级**：`#` 只能标块、标不了字段（答案、解析仍须另找一套记号），格式里会并存两套；层级深度也被 `#` 的数量绑死。
- **HTML 式闭合标签**（`<题目>…</题目>`）：啰嗦，且数学内容里的 `x<y` 会与标签定界符冲突。
- **`@…@` 对称定界**：单个 `@` 与关键字命名空间撞车——`@x>0@` 的开头会被读成关键字 `x`。

## 后果

- 父规范（#1）中「文档用类 Markdown 但更严格的语法书写」不再成立，须修订。
- CONTEXT.md 的「行内公式」条目由 `$…$` 改为 `@math{…}`。
- 记号与 Markdown 预览器不兼容：本格式的源文件在 Markdown 查看器里不会好看，这是刻意取舍——换来的是结构在源文件里肉眼可辨。
